# Задание для Claude Code: установить Telegram-агента

Ты — Claude Code на Linux-сервере или компьютере человека. Сделай так, чтобы человек мог писать тебе в Telegram, когда он не у компьютера. Сообщения должны попадать в постоянно запущенную сессию Claude Code, и отвечать ты должен туда же. У сессии все обычные возможности: файлы, команды, поиск, фоновые задачи. Telegram служит только входом и выходом.

Человек, скорее всего, не программист. Говори с ним просто, без терминов. Каждый шаг проверяй на деле: запусти и посмотри вывод. Не говори «готово», пока не пройдена проверка из шага 9.

## Как это устроено (для тебя)

- Официальный плагин `telegram@claude-plugins-official` — сервер MCP на Bun. Он опрашивает бота, передаёт сообщения в сессию и даёт ей инструменты `reply`, `react`, `edit_message`, `download_attachment`.
- Сессия запускается как `claude --channels plugin:telegram@claude-plugins-official`. Ей нужен терминал, поэтому она живёт в `tmux`, а `tmux` запускает пользовательская служба systemd `tg-agent` с автоперезапуском.
- **Плагин включён только для этой сессии** через отдельный файл `--settings`, глобально он выключен. Бота может опрашивать только один процесс. Если включить плагин глобально, любая другая сессия Claude заберёт бота себе.
- Скрипт `patch.py` из этого набора дорабатывает установленный плагин: команда `/new`, архив переписки, пересылки, отправка фото без сжатия, команды `/now`, `/stop`, `/usage`, `/today` и подтверждение после перезапуска.
- Скрипт `agent.py` выполняет команды из меню бота (`/now`, `/stop`, `/usage`), перезапуск с подтверждением и ночную уборку. Его вызывают плагин и таймер, человеку запускать его не нужно.
- Всё ставится **под обычным пользователем, без root**. Набор лежит в `~/.local/share/telegram-agent`, рабочая папка агента — `~/telegram-agent`.

## Когда нужен пароль администратора

У тебя нет прав root, и обходить это не надо. Если команде нужен `sudo`, не запускай её сам. Дай человеку готовую строку и объясни так:

> Нужна одна команда с правами администратора. Откройте терминал на этом сервере (там же, где вы запустили меня), вставьте строку ниже и нажмите Enter. Попросит пароль — введите пароль от этого компьютера или сервера. Символы при вводе не видны, это нормально. Когда закончится, напишите мне «готово».

Если человек работает под root (`id -u` равен 0), sudo не нужен, но служба и пути станут `/root/...`. Предложи ему создать обычного пользователя. Если он откажется, ставь под root и поменяй пути.

## Шаг 0. Спросить у человека

1. **Создать бота.** Объясни так: «Откройте в Telegram @BotFather, отправьте `/newbot`, придумайте имя и адрес бота (адрес должен кончаться на `bot`). BotFather пришлёт токен — длинную строку вида `123456789:AA…`. Пришлите её мне». Токен — это пароль от бота. Нигде его не показывай, кроме файла `.env` (шаг 4).
2. **Часовой пояс** для времени в архиве. По умолчанию Москва.
3. **Ночная ревизия.** Объясни: «Каждую ночь бот может перечитывать переписку за день и записывать важное в свои файлы, чтобы ничего не забыть. Это тратит немного лимитов подписки. Включить?» По умолчанию выключена. Напоминание про `/new` работает в любом случае, оно бесплатное.

Свой Telegram ID человеку искать не нужно: доступ откроем через код подтверждения (шаг 7).

## Шаг 1. Проверить, что есть

```bash
cat /etc/os-release | head -2; id -u; free -h | head -2
command -v systemctl tmux git python3 curl unzip; ls ~/.local/bin/claude ~/.bun/bin/bun 2>&1
claude --version && claude -p "ответь одним словом: ок"
```

- Нет `systemctl` — служба systemd не подойдёт. Скажи человеку, что этот набор пока только для Linux с systemd.
- Нет `tmux`, `git`, `unzip` или `curl` — дай человеку строку с sudo: `sudo apt-get update && sudo apt-get install -y tmux git unzip curl` (или аналог для его системы).
- Claude Code должен быть в `~/.local/bin/claude`. Если его там нет, поставь: `curl -fsSL https://claude.ai/install.sh | bash`.
- Если `claude -p` просит войти: попроси человека запустить `claude` в терминале и выполнить `/login`. Если после «Authorize» в браузере не открылась страница `http://localhost:…/callback?…`, вход завершают так: скопировать адрес из браузера и выполнить на сервере `curl 'адрес'`. Адрес обязательно в одинарных кавычках, в нём есть `&`.
- Bun: `curl -fsSL https://bun.sh/install | bash`. Проверь `~/.bun/bin/bun --version`. Чтобы служба нашла bun без `.bashrc`, сделай ссылку: `mkdir -p ~/.local/bin && ln -sf ~/.bun/bin/bun ~/.local/bin/bun`.

## Шаг 2. Набор и плагин

```bash
git clone https://github.com/gregorythejam/claude-telegram-agent ~/.local/share/telegram-agent
claude plugin install telegram@claude-plugins-official
# если ругается на маркетплейс: claude plugin marketplace add anthropics/claude-plugins-official, потом повторить
```

Открой `~/.claude/settings.json` и выключи плагин глобально, остальные ключи не трогай:
```json
"enabledPlugins": { "telegram@claude-plugins-official": false }
```
Затем:
```bash
cp ~/.local/share/telegram-agent/templates/tg-agent.settings.json ~/.claude/tg-agent.settings.json
python3 ~/.local/share/telegram-agent/patch.py
```
`patch.py` должен написать про каждую правку «поставлена». Если какая-то «не подошла», плагин обновился и правка к нему не подходит. Бот будет работать и без неё. Скажи человеку, какой возможности не будет.

## Шаг 3. Рабочая папка

```bash
mkdir -p ~/telegram-agent/дела ~/telegram-agent/архив-переписки
cp ~/.local/share/telegram-agent/templates/CLAUDE.md ~/telegram-agent/CLAUDE.md
```
Если у человека уже есть папка с проектами и он хочет, чтобы агент работал в ней, это можно сделать позже. Для первого запуска нужна отдельная пустая папка.

## Шаг 4. Токен и доступ

```bash
mkdir -p ~/.claude/channels/telegram && chmod 700 ~/.claude/channels/telegram
( umask 077; printf 'TELEGRAM_BOT_TOKEN=%s\n' 'ТОКЕН' > ~/.claude/channels/telegram/.env )
( umask 077; printf '{"dmPolicy":"pairing","allowFrom":[],"groups":{},"pending":{}}\n' > ~/.claude/channels/telegram/access.json )
```
Подставь токен и не выводи его в чат. Проверь, что токен живой, не печатая его:
```bash
T=$(cut -d= -f2- ~/.claude/channels/telegram/.env); curl -s "https://api.telegram.org/bot$T/getMe" | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d["ok"], d.get("result",{}).get("username"))'
```

## Шаг 5. Служба

```bash
mkdir -p ~/.config/systemd/user
cp ~/.local/share/telegram-agent/templates/tg-agent.service ~/.config/systemd/user/
```
Если часовой пояс не московский, поправь строку `TZ=` в службе (например, `Europe/Samara`, `Asia/Yekaterinburg`).

Чтобы служба работала, когда человек не залогинен, и поднималась после перезагрузки, проверь `loginctl show-user "$USER" -p Linger`. Если там `no`, дай человеку строку с sudo: `sudo loginctl enable-linger <имя пользователя>`.

```bash
systemctl --user daemon-reload
systemctl --user enable --now tg-agent
sleep 20; tmux -L tg-agent capture-pane -p -t tg-agent | tail -30
```

Ночная уборка (03:30): напоминание про `/new`, когда разговор разросся (больше 150 тыс. токенов, не чаще раза в три дня), и ревизия дел, если человек её включил.
```bash
cp ~/.local/share/telegram-agent/templates/tg-agent-night.{service,timer} ~/.config/systemd/user/
```
Если человек включил ревизию, поставь в `tg-agent-night.service` `TG_NIGHT_REVISE=1`. Часовой пояс поправь там же и в `tg-agent-night.timer`, как в службе.
```bash
systemctl --user daemon-reload && systemctl --user enable --now tg-agent-night.timer
systemctl --user list-timers tg-agent-night.timer
```

## Шаг 6. Первый запуск: ответить на вопросы сессии

Первый запуск почти всегда останавливается на вопросе: доверять ли папке, согласен ли с режимом и т. п. Прочитай экран через `capture-pane`, ответь клавишами (`tmux -L tg-agent send-keys -t tg-agent Enter` или нужная цифра и Enter) и снова прочитай экран. Сессия готова, когда видно поле ввода `❯` без диалогов.

- Если режим `auto` не запускается (тариф не поддерживает), поменяй в службе `TG_PERMISSION_MODE=default`. Тогда на рискованные действия бот будет спрашивать разрешение кнопками в Telegram. Скажи об этом человеку.
- Плагин поднялся, если у процесса claude есть дочерний `bun … server.ts`: `pgrep -af 'bun.*server.ts'`.

## Шаг 7. Пустить владельца

Скажи человеку: «Напишите своему боту в Telegram любое сообщение. Он ответит кодом из шести символов. Пришлите код мне».

Когда пришлёт, найди этот код в `pending` файла `~/.claude/channels/telegram/access.json`. Перенеси `senderId` в `allowFrom` (строкой), очисти `pending` и поставь `"dmPolicy": "allowlist"`. Плагин перечитывает файл на каждом сообщении, перезапуск не нужен. Теперь бот отвечает только владельцу, остальных молча игнорирует.

Другого человека пускают так же: временно `pairing`, он пишет боту, код, перенос в `allowFrom`, снова `allowlist`. Надолго `pairing` не оставляй: бот будет отвечать кодами посторонним.

## Шаг 8. Голосовые (по желанию)

Спроси, нужны ли голосовые. Расшифровка идёт на самом сервере, без внешних сервисов. Модели `small` нужно около 1 ГБ памяти, модели `large-v3-turbo` — около 2 ГБ, у неё лучше качество для русского. Модель выбирай по `free -h`.

Нужен модуль venv: если `python3 -m venv /tmp/x` падает, дай строку `sudo apt-get install -y python3-venv`.
```bash
python3 -m venv ~/.local/share/tg-voice && ~/.local/share/tg-voice/bin/pip install faster-whisper
cat > ~/.local/share/tg-voice/transcribe.py <<'PY'
"""tg-voice <файл> -> текст"""
import os, sys
from faster_whisper import WhisperModel
model = WhisperModel(os.environ.get("TG_VOICE_MODEL", "small"), device="cpu", compute_type="int8", cpu_threads=os.cpu_count())
segments, _ = model.transcribe(sys.argv[1], language="ru", vad_filter=True)
print(" ".join(s.text.strip() for s in segments))
PY
printf '#!/bin/sh\nexec %s/.local/share/tg-voice/bin/python %s/.local/share/tg-voice/transcribe.py "$@"\n' "$HOME" "$HOME" > ~/.local/bin/tg-voice
chmod +x ~/.local/bin/tg-voice
```
Для большой модели добавь в обёртку `export TG_VOICE_MODEL=large-v3-turbo`. Первый запуск скачает модель.

## Шаг 9. Проверка с телефона (обязательно)

Попроси человека сделать по очереди и после каждого пункта сверь результат:

1. Написать «привет». Бот отвечает.
2. Прислать фото с вопросом. Бот отвечает по фото.
3. Попросить «пришли это фото обратно файлом». Фото приходит документом, без сжатия.
4. Переслать пост из любого канала. Бот знает, откуда пост.
5. Голосовое, если ставили. Сначала приходит расшифровка, потом ответ.
6. Нажать `/new` (есть в меню бота). Приходит «Начинаю новый диалог», через полминуты «✅ Новый диалог начат».
7. Написать что-то по теме из пункта 2, не объясняя. Бот находит её в `архив-переписки/` и отвечает по делу.
8. Проверить, что в `~/telegram-agent/архив-переписки/` появился файл за сегодня с этой перепиской.
9. Нажать `/usage`. Через 5–10 секунд приходит расход лимитов за 5 часов и неделю.
10. Попросить что-то долгое («найди в интернете три свежие новости про … и сделай сводку») и, пока бот работает, нажать `/now`. Приходит «🟢 Работаю» и последние шаги. Затем `/stop`: приходит «⏹ Остановил».
11. Нажать `/today`. Бот присылает итоги дня.
12. Написать «перезапустись». Бот пишет, что перезапускается, через полминуты приходит «✅ Перезапустился, разговор тот же», и бот помнит, о чём шла речь.

Если что-то не работает, смотри «Если бот молчит» ниже, исправь и повтори пункт.

## Шаг 10. Рассказать человеку, как пользоваться

Коротко и простыми словами:
- Пишите боту как человеку. Можно текст, фото, файлы, голосовые и пересланные посты.
- Начинаете **новую тему** — нажмите `/new`. Бот начнёт с чистого листа и будет отвечать быстрее, а лимиты подписки будут тратиться медленнее: иначе каждый ответ тащит за собой всю прошлую переписку. Всё важное бот записывает в файлы и найдёт, если вернуться к старой теме.
- Остальные команды в меню бота (кнопка «/» или «Меню»): `/now` — что бот делает прямо сейчас; `/stop` — остановить текущую работу; `/usage` — сколько лимитов подписки потрачено; `/today` — итоги дня. `/now`, `/stop` и `/usage` срабатывают сразу, даже когда бот занят.
- «Перезапустись» — бот перезапустится и продолжит тот же разговор. Помогает, если он завис. Контекст при этом не очищается, для этого `/new`.
- Если плагин обновится, `/new` может пропасть. Тогда попросите Claude на сервере: «запусти `python3 ~/.local/share/telegram-agent/patch.py` и перезапусти tg-agent».

## Обслуживание

| Что | Команда |
| --- | --- |
| Состояние | `systemctl --user status tg-agent` |
| Экран сессии | `tmux -L tg-agent capture-pane -p -t tg-agent \| tail -40` |
| Подключиться к экрану | `tmux -L tg-agent attach -t tg-agent` (выйти: Ctrl+B, потом D; Ctrl+C не нажимать) |
| Перезапуск (разговор сохранится) | `systemctl --user restart tg-agent` или `python3 ~/.local/share/telegram-agent/agent.py restart` (с подтверждением в Telegram) |
| Ночная уборка | `systemctl --user list-timers tg-agent-night.timer`; журнал команд — `~/.local/state/telegram-agent.log` |
| Выключить | `systemctl --user disable --now tg-agent` |
| Вернуть доработки после обновления плагина | `python3 ~/.local/share/telegram-agent/patch.py`, затем перезапуск |
| Обновить набор | `git -C ~/.local/share/telegram-agent pull`, затем `patch.py` и перезапуск |

**Если бот молчит:**
1. Служба запущена? `systemctl --user status tg-agent`.
2. Есть процесс `bun … server.ts`?
3. Не висит ли в tmux вопрос? Быстро проверить с телефона: `/now`. Иногда всплывает окно вроде «Teach auto mode about your environment?». Новые сообщения оно не блокирует, но клавиши в tmux без нужды не отправляй: символ может попасть в поле ввода.
4. Не открыта ли ещё одна сессия с `--channels` на этот же токен и не включён ли плагин глобально?

**Чего не делать:** не выводить токен в чат и логи; не открывать порты наружу (агенту они не нужны, бот сам ходит к Telegram); не запускать вторую копию.
